## 三、问题清单

### AR-01（部署 / 服务器）chroot 模式下 `-config` 传宿主路径导致起服失败并退化为单机客户端

- 现象：Linux 云主机以 chroot 模式启动服务器时，`-config` 传入的是宿主路径，
  chroot 内不可见；服务器启动失败，进程退化成单机客户端（不监听 7777）。
- 影响：云主机部署流程不可用；若未及时发现，会误以为云服在线。
- 复现：云主机设置 `RAIDDEMO_CHROOT` 后执行 `./server.sh restart`（脚本拼接宿主路径 `-config`）。
- 期望 vs 实际：期望 chroot 内应用配置并监听 7777；实际未监听且进程形态错误。
- 疑似模块：`deploy/server.sh` chroot 分支 + 服务器 `-config` 路径解析。
- 严重级：中（有环境变量规避，但部署脚本本身仍会踩）。
- 规避：改用环境变量传配置路径，服务器恢复正常（当前云服即以此方式运行）。
- 状态：**本轮只记录，不修复**；修复排期另行安排。
- 证据：

### AR-07（服务器性能，中）4 人局同机环境下服务器主线程频繁卡顿，导致客户端掉线重连

- 现象：1 服务端 + 4 客户端（2 窗口 + 2 无头）跑在同一台机器时，

  窗口端 UI 一度落到「联机」界面并显示"连接断开，正在重连…"。
- 服务端日志自带因果说明：`[诊断] 服务器 主线程卡顿 0.75 秒…这类停顿会让 NGO 心跳超时，
  对面看到的就是掉线。`
- 影响：联机中的位置卡顿、短暂掉线重连；4 人局的体验受直接损害。
- 复现：① 本机 1 服 + 4 客户端 → 日志出现 0.59~0.75 秒卡顿与多次重连；
  ② 云主机 2 核 + 2 客户端 → 日志出现 0.68/0.72 秒卡顿。
- 期望 vs 实际：期望服务器帧时间稳定（无秒级停顿）；实际出现 0.6~0.75 秒级卡顿并触发心跳超时。
- 疑似模块：服务器主循环峰值（物理 / 快照序列化 / 渲染管线更新，需采样定位）。
- 严重级：中（云上 2 人即复现；玩家侧表现为掉线与卡顿）。
- 待确认：卡顿是否由"同机再跑 4 个客户端"抢占资源造成；批次 3（云主机 + 本机 2 客户端）
  做同口径对比，若云上仍复现则升级为独立性能缺陷。
- 证据：`Builds/ServerWindows/Logs/server.log` 第 243~281 行区间；
  `mp-r2-c-after-host-left.png`。
- 升级（云主机对比）：2 核云主机在**仅 2 人**时也出现
  `主线程卡顿 0.72 秒 / 0.68 秒`（云 `server.log` 第 385、397 行），
  说明卡顿不是"本机再跑 4 个客户端"独有，需单独立项排查（疑似 URP/物理/快照序列化峰值）。

## 五、结论

- 三条链路（单机 / 本地服务器 / 云服务器）都能跑通主闭环：
  **入局 → 进图 → 搜刮/战斗 → 撤离或阵亡/超时 → 结算 → 回安全屋**；
  4 人联机（含 2 个无头机器人）在本地与云上都能进同一房间、同一战局，并完成撤离入库。
- 分发链路验证通过：本机与云更新源 242 文件 / 0 差异；0.10.1 旧客户端被版本握手拒绝并提示两个版本号；
  更新源不可用时有明确失败提示。
- 阻断级问题 1 条：**AR-06 联机无法返回主菜单（U-93 #9 修复未见效）**；
  中等问题 5 条：AR-01（部署脚本 chroot 路径）、AR-03（撤离圈不一致）、AR-04（单个 AI 不攻击）、
  AR-07（服务器主线程卡顿，云上 2 人即复现）、AR-08（默认配发可刷入库）；
  低等问题 2 条：AR-02、AR-05（均为结算显示/统计口径）。
- **结论：1.0.0 可作为演示与联机验收版本继续使用**；建议下一轮优先修 AR-06 与 AR-07，
  AR-08 由负责人拍板口径，其余按排期处理。
- 本轮**未修改任何代码**；全部问题只记录，修复方案与排期另行安排。
