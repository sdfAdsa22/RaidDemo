## 三、问题清单

### M13-01（P1）同一安装根并发更新无互斥；启动器无单实例保护

- **现象**：两个启动器同时更新同一安装根 → 必有一方失败，报错为原始英文；日志出现"校验大小不符"，即读到了另一进程写入的字节。
- **证据**：
  - `Builds/LauncherTestM13/n7b-concurrent/`：JOB1 退出码 1，`替换文件失败（已回滚）：Could not find file '…\staging\body\cross_saves_A旧服务器新客户端\accounts.json'`；JOB2 退出码 0（本轮我实测）。
  - `Library/TestRuns/M13/followups.txt`：并发两次 `--update` → 进程1 退出码 0、进程2 `The process cannot access the file 'accounts.json' because it is being used by another process.`。
  - GUI 侧（本轮实测）：双击两次 exe → 两个独立进程、两个"RaidDemo 启动器"窗口并存，各自都能点"下载"。
- **根因**：暂存路径只由"安装根+层+相对路径"决定（`Tools/Launcher/Update/UpdateApplier.cs:77`），每个进程开头清空整层暂存
  （`UpdateApplier.cs:166` / `UpdateSession.cs:249`），而校验在下载中、落盘在全部下载完成后（`UpdateSession.cs:333`），
  中间窗口可达数分钟；全工程无跨进程互斥（`rg Mutex Tools/Launcher` 无命中）。
- **建议**：命名 `Mutex`（键含安装根）+ staging 按会话隔离 + 落盘前复校；GUI 另加单实例（激活已有窗口）。

### M13-02（P1）清单路径未做归位校验，可写出/删除安装根之外

- **现象**：清单里放 `path = "..\escape-probe.txt"` 的条目，`--update` 会**在安装根上一级写文件**并返回退出码 0；
  把该条目移除再跑，该外部文件会被**删除**。
- **证据**：`Builds/LauncherTestM13/m13-audit/traverse-src/`（含 `escape-probe.txt` 与清单）、`traverse-root/`；
  审计报告 `M13_更新流程审计.md` F2 记录了完整命令与结果。
- **根因**：`ManifestFileEntry.NormalizePath`（`Assets/Game/Kernel/Pure/Updates/UpdateManifest.cs:166`）不处理 `..`；
  目标路径直接 `Path.Combine(installRoot, change.Path)`（`UpdateSession.cs:333`），删除同理（`UpdateApplier.cs:271`）；
  盘符绝对路径会按 `Path.Combine` 语义替换安装根。
- **建议**：统一 `ResolveInsideRoot`；清单解析期拒绝 `..`/盘符/绝对路径条目；补 EditMode 负例。

### M13-03（P1）设置抽屉：手输"安装目录"后直接点"保存设置"会静默丢设置

- **现象**：在"安装目录"输入框里键盘输入新路径 → 直接点"保存设置" → 界面提示"设置已保存"、日志写"已保存设置"，
  但 `launcher.config.local.json` 里 `InstallRoot` **仍是旧值**、新目录未创建；输入框仍显示新路径 → 界面与实际不一致。
- **对比实验**：同样输入后先按 `Tab`（让输入框失焦）再保存 → 配置正确写入，且自动追加 `RaidDemo` 子目录、目录被创建。
- **真实鼠标确证（补充实测）**：用 `SetCursorPos + mouse_event` 注入**物理鼠标**点击"保存设置"（输入框保持焦点、未按 Tab）→
  日志出现"已保存设置"、状态行显示"设置已保存"，而配置 `InstallRoot` 仍是旧值 `…\gui-close3\RaidDemo`，新输入的 `…\gui-mouse` 被丢弃
  （证据：`Builds/LauncherTestM13/gui-close3/RaidDemo/.raiddemo/launcher.log` 08:35:02 行；脚本 `Library/TestRuns/M13/physical_mouse_save_test.ps1`）。
  **结论：真实用户鼠标路径同样复现，不是自动化伪影。**
- **根因（初判）**：`InstallRootRow.m_Text.Leave += Apply(...)`（`Tools/Launcher/InstallRootRow.cs:79`）；
  "保存设置"是自绘 `Panel`（不抢焦点），点它不会触发 `Leave`，`TrySaveSettings` 直接落盘旧值
  （`LauncherForm.Drawer.cs` 的 `TrySaveSettings`）。
- **建议**：保存前显式提交编辑框（调用与 `Apply` 相同的路径），或把 Apply 挂到 `TextChanged`/`Validated`。

### M13-04（P2）内容缓存与 `state.json` 是机器级共享，后写覆盖先写

- **现象**：不同安装根共用 `%USERPROFILE%\AppData\LocalLow\RaidDemo\RaidDemo\content`；`state.json` 直接覆写，无协调。
- **证据**：`ContentCacheInstaller.ResolveGameDataRoot`（`Tools/Launcher/Update/ContentCacheInstaller.cs:165`）只用公司名/产品名；
  `WriteState`（同文件 142 行）`File.WriteAllText`；本机 `state.json` 的 `updatedAt=2026-09-18T08:07:35` 由 `gui-run1` 写入。
- **建议**：临时文件 + 原子替换；并入 M13-01 的互斥区；多安装根场景考虑按安装根隔离（需与游戏侧同步）。

### M13-05（P3）失败原因把 .NET 英文原文直接透给玩家

- **证据**：`N5 安装根是文件`：`更新失败：Cannot create '…' because a file or directory with the same name already exists.`；
  `N7b`：`Could not find file '…'`；并发用例：`The process cannot access the file … because it is being used by another process.`
  （GUI 弹窗、CLI 输出、日志三处同源）。

### M13-06（P3）清单缺 `body` 层被当成"已是最新版本"

- **证据**：`N4`（清单只有 `schemaVersion/generatedAt`）：`退出码=0 | 已是最新版本（本体 未知）。`；
  `N11`（空 files + version 9.9.9）：`退出码=0 | 已是最新版本（本体 9.9.9）。`
- **影响**：源发布错误看起来像"成功且最新"。
- **建议**：缺 `body`、`files` 为空、`version` 缺失时判为清单无效并报错退出。

### M13-07（P3）失败/中断后暂存区残留

- **证据（本轮实测）**：云源全量下载中途关窗 → 安装根只有 `.raiddemo/staging/` 下 31 个半成品文件（32 文件/34 MB），**无本地清单快照**；
  审计侧失败用例残留 153 MB 级；只有下次更新开头才清理。重开后再点"下载"能正常收敛（244 文件、快照 1.0.6、staging 目录消失）。
- **建议**：进程退出/启动时清理本会话 staging；失败路径主动清理（保留"续传"能力的话按会话目录管理）。

### M13-08（P3）隐藏源的两处口径不一致

### M13-09（P3）长状态文案被右边缘裁切

### M13-12（P3）CLI 输出编码依赖宿主，非 UTF-8 捕获时中文乱码

- **证据**：`Start-Job` 捕获子进程输出时出现 `鏇存柊婧愶細…`（UTF-8 字节按 GBK 解码）；直接在当前控制台运行正常。
  `Program.cs:52-61` 用 `UTF8Encoding(false)` 包装 `Console.Out`（无 BOM）。
- **建议**：脚本侧约定 `[Console]::OutputEncoding = UTF8`（本轮脚本已如此）；若要兼容任意宿主可考虑 BOM 或 ASCII 兜底。

### M13-13（P3，待复现确认）同秒内连续多次更新时备份目录数偏少

- **修订（补充实测）**：首轮 `followups.txt` 的异常数字（0/1 份）来自**测试脚本自身的时序问题**——
  `$null = & $launcher … 2>&1` 在本次 PowerShell 环境下没有按预期串行等待，导致"全量安装"与"第一次增量"并发互相踩
  （日志里同秒多条"命令行启动"、`staging` 文件被对方清掉）。
  改用 `Start-Process -Wait` 严格串行后（`followups2.ps1` / `followups2.txt`），实验 3a（跨秒三次增量）→ 备份 **2 份且内容正确**，
  实验 3b（连续两次增量）→ 2 份，均符合"保留最近两份"设计。**M13-13 不作为缺陷**，仅保留"备份目录名秒级时间戳在极快连续更新下可能合并"的理论观察。
- 附带教训（排障章节已记）：驱动启动器做时序敏感的批量实验必须用 `Start-Process -Wait`。

### M13-14（P3，观察）相对 `--root` 的解析基准是"当前工作目录"

- **证据**：`N9`：`--root relative-root-m13` 的落点在 cwd（True），不在启动器目录（False）。
- **说明**：CLI 语义如此（便于脚本），但文档未写；GUI 默认 `InstallRoot="RaidDemo"` 解析到 **exe 所在目录**。
- **建议**：在 `--help`/文档里写明两者的基准差异。

### M13-15（P1）游戏内热更：明文 HTTP 更新源被 Player Settings 拒绝

- **现象**：用启动器"开始游戏"启动的客户端，启动后立即在 `Player.log` 抛出：
  `Non-secure network connections disabled in Player Settings` /
  `InvalidOperationException: Insecure connection not allowed`（`HotUpdateClient.FetchManifestText`）。
- **证据**：`%USERPROFILE%\AppData\LocalLow\RaidDemo\RaidDemo\Player.log`（2026-09-18 08:28 与 08:30 两次启动均复现，日志字节数一致）。
  启动器日志的启动参数为：`-updatesource "http://47.104.210.207:8090" -serverhost "47.104.210.207" -hideserver`。
- **影响**：交付构建里**游戏内热更（资源层检查/下载）必然失败**；当前演示靠启动器预装内容层绕过（M12 遗留 9.4 的根因之一）。
- **根因（初判）**：Player Settings 的 "Allow downloads over HTTP" 默认为 Not allowed，而更新源是明文 HTTP。
- **建议**：二选一——A. Player Settings 显式允许 HTTP（演示口径，改动最小）；B. 更新源上 HTTPS（正式口径）。
  修复后需实测"游戏内跨内容版本更新"链路（M12 遗留项一并关闭）。

### M13-16（观察，非缺陷）游戏分辨率/坐标体系（排障用）

- 本机显示器：**2560×1440 物理 / 150% 缩放**（逻辑 1707×960）；游戏窗口以 2560×1440 级尺寸运行（含边框 2582×1496），符合全屏窗口预期。
- 自动化操作注意：此类窗口的**截图坐标（物理像素）与注入坐标系（sky 逻辑坐标）不一致**，
  实际点击需按"物理截图坐标 ÷ 缩放比"换算或用 `SetCursorPos + mouse_event` 直接注入物理坐标；
  启动器窗口（DPI 感知）则按物理坐标直接可用。排障章节已记。

### M13-18（P3）四个窗口控制按钮（关闭/最小化/设置/日志）无无障碍名称

### M13-19（P2）"恢复默认"按钮实测无效

- **现象**：点"恢复默认" → 状态行提示"已恢复默认值（点「保存设置」）"，但抽屉里的"更新源/地址/游戏服务器"字段**没有变化**（仍显示当前值）；
  随后点"保存设置" → `launcher.config.local.json` 的 `SelectedSource` 仍是"本机"（而非模板默认"云主机"）。
- **证据**：本轮实测（`Library/TestRuns/M13/gui/launcher.config.local.json` 保存后 `SelectedSource="本机"`）；
  代码 `OnRestoreDefaults()` 用 `LauncherConfig.Load(string.Empty)` 取"默认值"，而空参数下 `Path.Combine("", 文件名)` 是
  **相对当前工作目录**的路径——正好读到启动器目录里的 local 配置，等于"恢复成当前值"；另外安装目录那行用的是旧 `m_Config`。
- **建议**：改用 `LauncherConfig.CreateDefault()`（或显式忽略 local 的加载入口），并让安装目录行显示 defaults 的值。

## 六、复现环境与排障

- 本机更新源：`Tools/UpdateSource/RaidDemo.UpdateSource.exe`（监听 127.0.0.1:8090，根目录 `Builds/Update/1.0.6`）。
  电脑重启后需重新拉起；判断是否在线：`Invoke-WebRequest http://127.0.0.1:8090/manifest.json` 应 200。
- 云源：`http://47.104.210.207:8090`（管理页 `http://47.104.210.207:8080/`，口令见 `Docs/12_用户反馈问题记录.md` U-101）。
- 沙盒与脚本：`Library/TestRuns/M13/*.ps1|txt`（不入库）；审计材料 `Builds/LauncherTestM13/m13-audit/`（不入库）。
- 已知环境噪声：`Start-Job` 捕获子进程输出会 GBK 误码（M13-12），脚本里需要 `[Console]::OutputEncoding = UTF8`。
- 启动器 GUI 无 UIA 元素名时，可用窗口相对坐标操作；日志窗口用 `Esc` 关闭；抽屉展开时右上角图标不可见，关闭窗口需先"收起"。

  游戏侧操作改用 `Library/TestRuns/tools/GameWindow.ps1` 的 `Click-RaidDemoAt`（物理屏幕绝对坐标）；启动器窗口按物理坐标可直接点。
- **批量时序实验**：驱动启动器跑"连续多次更新"必须用 `Start-Process -Wait`（`& exe` 在本机 PowerShell 环境下不保证等待，会造成假并发）。
- **物理鼠标确证法**：`SetCursorPos + mouse_event`（见 `physical_mouse_save_test.ps1`），用于排除"UIA 点击不转移焦点"造成的自动化伪影。
