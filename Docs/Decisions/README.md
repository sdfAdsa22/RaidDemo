# 架构决策记录（ADR）

本目录用于记录项目中**影响面较大的技术决策**，目的有两个：

1. 让未来的自己（或接手者）知道"为什么当初这么选"，避免反复推翻已有设计。
2. 在面试中提供真实的技术取舍素材 —— "我考虑过 A 和 B，最后因为 C 选了 D"远比"我用了 D"有说服力。

## 何时需要写 ADR

- 引入或移除一个第三方包
- 更改模块划分或程序集依赖方向
- 更换核心算法或数据存储方案（如序列化方式、寻路方案）
- 决定"不做某功能"（Anti-Scope 条目）

## 文件命名

```text
ADR-001-采用JsonUtility作为存档序列化方案.md
ADR-002-采用状态机而非行为树实现AI.md
```

编号三位数、递增、不复用。

## 模板

```markdown
# ADR-XXX：决策标题

- 状态：提议中 / 已采纳 / 已废弃（被 ADR-YYY 取代）
- 日期：YYYY-MM-DD
- 相关代码：仓库相对路径

## 背景

描述当前面临的问题与约束条件（如引擎版本限制、IL2CPP 兼容性要求、开发周期）。

## 候选方案

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| A | ... | ... |
| B | ... | ... |

## 决策

选择哪个方案，一句话说清。

## 理由

为什么它优于其他候选（结合本项目的实际约束，而非泛泛而谈）。

## 后果

- 正面影响
- 需要承担的代价与后续待办
```
