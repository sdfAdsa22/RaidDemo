# ADR-005：对标基线修正为《逃离鸭科夫》

- 状态：已采纳
- 日期：2026-09-10
- 影响范围：全部玩法系统设计（武器、AI、局外系统、移动）

## 背景

项目前期（准备阶段至 M0）的技术文档与设计决策**没有写明对标游戏**。
在缺乏参照系的情况下，设计决策不自觉地滑向了知名度更高的《逃离塔科夫》，
具体表现为两条已经提出的建议：

1. 保留蹲下姿态（理由是"服务潜行博弈"）
2. 让体力影响射击精度（理由是"制造跑动与射击的取舍"）

项目负责人在 M1 开工前明确：对标游戏是 **《逃离鸭科夫》（Escape from Duckov）**，
而非塔科夫。这直接推翻了上述两项建议。

## 两款游戏的差异（决策依据）

| 维度 | 《逃离塔科夫》 | 《逃离鸭科夫》 |
| --- | --- | --- |
| 对抗对象 | PvP 为主，残酷博弈 | PvE 为主 |
| 紧张感来源 | 对枪、穿甲计算、被蹲守 | 贪心与撤离时机 |
| 死亡代价 | 极高，装备全丢 | 相对宽容 |
| 射击手感 | 拟真，大量惩罚项 | 爽快、宽容 |
| 美术风格 | 写实硬核 | 卡通鸭子 |
| 装备系统 | 拟真护甲等级与穿透力 | 装备等级驱动成长 |
| 撤离点 | 条件严苛 | 相对友好 |

**核心差别**：塔科夫的张力来自"我会不会死"，鸭科夫的张力来自"我该不该再贪一件"。

## 候选方案

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A. 继续沿用塔科夫式设计 | 文档已按此写就，改动成本最低 | **否决**：与项目负责人的实际目标不符 |
| B. 全面重写文档 | 最彻底，但会丢弃大量与品类无关的正确内容 | 否决：过度返工 |
| **C. 增量修正** | 保留品类通用内容（核心循环、网格背包、AI 架构），仅修正受塔科夫影响的部分 | **采纳** |

## 决策

采用 **方案 C**，并在文档中补充 **1.3 节「对标基线」**作为强制参照系。

## 具体修正内容

| 位置 | 原设计（塔科夫式） | 修正后 |
| --- | --- | --- |
| 1.3 节 | 无对标基线章节 | 新增，含两款游戏差异对照与四条设计原则 |
| 7.3 节 武器与弹道 | 穿透概率公式、头/胸/四肢倍率、射程衰减穿透力 | 等级减伤模型、粗粒度暴击、无弹道下坠 |
| 7.4 节 AI 感知 | 听觉按**姿态**分档 | 听觉按**移动速度**分档（姿态已砍掉） |
| 7.5 节 撤离规则 | 部分撤离点带附加条件 | 主流撤离点无条件可用 |
| 7.6 节 局外系统 | 装备仅为物品；含保险系统 | 新增装备等级与部位、收集图鉴；保险列入不做 |
| 7.12 节（新增） | 无 | 核心玩法支柱：贪婪循环及其系统映射 |
| 7.13 节（新增） | 无 | 移动、体力与负重；含决策修正记录 |
| 第 13 章 | — | 新增 4 条不做项（爬下、蹲下、体力影响射击、拟真弹道） |

## 未受影响的部分（明确保留）

以下内容与对标游戏无关，**不做任何修改**：

- 第 3 章：禁止绝对路径的工程约束
- 第 5 章：代码规范、程序集划分、注释规范
- 第 6 章：五层架构、事件总线设计
- 7.1 / 7.2 节：物品系统的静动态分离、网格背包规则
- 7.7 节：存档设计（版本号与迁移）
- 7.9 / 7.10 / 7.11 节：联机架构与热更新设计
- 第 8 章：测试策略、性能预算
- 第 9 章：里程碑划分（仅 M1 的内容描述有调整）
- 第 11 章：版本控制规范

**判断标准**：仓库结构、代码规范、网络与热更架构属于**工程范畴**，与玩法对标无关；
凡是描述"玩家体验到什么"的章节都需要重新审视。

## 后果

**正面影响**

- 设计决策有了明确参照，不再依赖对同类游戏的模糊印象。
- 移除了两项与项目基调冲突的机制（蹲下、体力惩罚射击），移动系统显著简化。
- 补上了此前缺失的核心设计——贪婪循环与其系统映射，使各模块有了统一的取舍依据。

**代价与后续待办**

- 7.3 节的护甲公式需要重新设计并在 M3 阶段调参验证。
- 7.6 节的装备等级系统是新增内容，实现量比原计划增加。
- 移动系统需要新增体力模块（原本不在 M1 范围内），M1 范围因此扩大。

**流程改进**

后续任何新系统的设计文档，**必须先在开头写明它对标基线中的哪条原则、如何强化贪婪循环**。
无法回答的功能应重新评估是否要做。
