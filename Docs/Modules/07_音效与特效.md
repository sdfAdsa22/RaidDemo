## 1. 这一批要解决什么

M0~M6 的灰盒阶段，射击只有一段**程序合成的白噪声**当枪声，命中也只是让靶子闪一下颜色。
它在"能玩"的意义上是够的，但离"完整作品"还差一层：**玩家判断自己有没有打中、打到了什么、周围有没有人开枪，
有一大半靠听觉与瞬时光效**。这一批把这三件事补齐，并且**不碰任何战斗数值**。

交付物：

| 类别 | 内容 |
| --- | --- |
| 音效资产 | 28 条加工后的 WAV（枪声 4、机械动作 5、命中 6、脚步 7、搜刮与撤离 6），随仓库提交 |
| 音效系统 | 音效目录 + 播放服务 + 事件导演 + 脚步节拍器 |
| 视觉特效 | 4 个粒子预制体（枪口火焰、命中火花、尘土、血雾）与池化播放器 |
| 武器模型 | 步枪 / 手枪项目层预制体，带枪口标记，替换灰盒立方体 |
| 接线层 | 表现层资产目录（一个资产管住全部引用）+ 场景接线工具 |
| 测试 | 29 条新增 EditMode 测试（音效触发 12 条 + 资产接线与动画接线 9 条 + 阵亡闸门 4 条 + 路径规则 1 条 + 其余 3 条） |

**没有改动**：战斗数值（射程、射速、弹匣、伤害、噪音半径）、AI 感知、背包与经济。
这一批从头到尾只动表现层与它的装配。

## 2. 音效素材加工管线

### 2.1 为什么不直接用素材库的原文件

The Free Firearm Sound Library 的每条录音都是**8~29 秒的完整素材**（枪响 + 长尾混响），
单条 5~16 MB、96 kHz 立体声 24 位。直接拿来"每开一枪播一次"会同时踩三个坑：

| 现象 | 原因 |
| --- | --- |
| 看到开火半秒后才听到声音 | 录音开头有 0.3~1.5 秒的环境底噪 |
| 下一发都打完了上一声还在响 | 录音总长远远超过射击间隔 |
| 内存里常驻几十 MB 音频 | 没有裁剪、没有降采样 |

### 2.2 加工做四件事

工具：`Assets/Game/Bootstrap/Editor/M7AudioBaker.cs`（流程）+ `M7AudioWavCodec.cs`（编解码）。

1. **自动定位起爆点**：按 1 毫秒窗口扫描 RMS，取第一个超过峰值 8% 的位置，从它前面 5 毫秒开始剪。
   这样枪声与画面同步，而不是"先看到枪口火焰、再听到枪响"。
2. **裁剪 + 淡出**：只保留设计时长（枪声 0.9 秒、机械动作 0.5 秒、提示音 1.2 秒），末尾 30 毫秒线性淡出。
3. **混单声道**：Unity 的 3D 空间音效只对单声道剪辑做声像与距离衰减，立体声剪辑会原地按 2D 播放。
4. **降采样到 48 kHz**：源素材是 96 kHz，用滑动平均（盒式滤波）降采样而不是直接隔点抽取，
   否则 24 kHz 以上的能量会折叠回可听频段，听起来像枪声里混了一层沙沙的金属噪声。

每条还要**峰值归一化**到统一电平，再由音效目录里的音量参数做混音——否则同一把枪的"近距"与"中距"
两条录音会相差十几个 dB，听起来像两把不同的枪。

### 2.3 选了哪些素材

| 用途 | 素材 | 为什么是它 |
| --- | --- | --- |
| 步枪枪声 | AK-47 的近距（`C_28P`）与中距（`C_31P`）单发 | 同一型号、两种录音距离，交替播放不会有重复感 |
| 手枪枪声 | 1911（`A_42P`）与 Walther PPQ（`X_39P`） | 两支枪音色差异明显，补上手枪射速慢、重复次数少的短板 |
| 机械动作 | Kenney Impact / Interface Sounds | 体积小、风格统一、CC0 |
| 脚步 | `footstep_grass_*` / `footstep_concrete_*` | 与地图的草地 + 水泥平台两种路面一一对应 |
| 搜刮与提示 | `open` / `scratch` / `select` / `tick` / `confirmation` / `error` | 开箱、翻找、拾取、撤离读秒、成功、失败 |

刻意**不用**连发与长点射录音（例如 `C_27P` 的 long burst）：本项目的射速由战斗层按毫秒精确控制，
音效必须"一发一份"，用连发录音会在停火后还剩半秒枪声。

## 3. 音效系统结构

### 3.1 三层分工

```text
AudioCatalog（资产）      「有哪些声音」——槽位清单，允许为空
        ↓
AudioService（引擎）      「怎么把声音播出去」——声部池、节流、空间化、音量
        ↓
GameAudioDirector（导演） 「什么时候该响」——订阅事件，翻译成 PlayAt / PlayFlat
FootstepAudioDirector        └ 脚步单独一个导演，因为它只关心移动事件
```

分层的收益：加一条新音效只动目录与导演，不用碰播放器；播放器的节流与池化策略只有一份实现。

### 3.2 播放服务要处理的三件事

| 问题 | 做法 |
| --- | --- |
| 全自动武器每秒十余发，按需创建 AudioSource 会产生 GC 峰值 | 固定 16 个 3D 声部 + 4 个 2D 声部轮流复用 |
| 同一帧多次请求同一条音效会叠成失真的一团噪声 | 同一条剪辑 35 毫秒内只播一次，超出直接丢弃 |
| 敌人从左边开枪却听不出方位 | 3D 声部走对数衰减，`minDistance` 3.5 米、最大距离按武器给（步枪 45 米 / 手枪 32 米） |

### 3.3 事件到声音的映射

| 事件 | 声音 | 空间化 |
| --- | --- | --- |
| `WeaponFiredEvent` | 步枪 / 手枪枪声（本地玩家按手持武器判定，其他人一律步枪） | 3D，位于枪口 |
| `WeaponFiredEvent`（命中） | 命中活体（闷响）或命中硬物（金属撞击） | 3D，位于命中点 |
| `ReloadStateChangedEvent` | 开始换弹 = 卸弹匣；完成 = 推弹匣 + 拉栓 | 仅本地玩家 |
| `LootSearchProgressEvent` | 每 0.45 秒一声翻找 | 仅本地玩家 |
| `LootSearchCompletedEvent` | 容器开启 | 2D |
| `InventoryChangedEvent`（放入 / 装备） | 拾取轻响 | 2D |
| `ExtractionProgressChangedEvent` | 每跨过 25% 进度响一声计次 | 2D |
| `ExtractionCompletedEvent` / `RaidEndedEvent` | 撤离成功 / 失败提示音 | 2D |

**只有本地玩家才有"自己"的动作音**：联机时若把队友的换弹也播出来，四个人的换弹声会盖住真正重要的枪声；
而枪声不同——枪声是战斗信息，敌人与队友的枪声都必须能听见方位。

### 3.4 俯视游戏的音量陷阱：听者在相机上

本项目的 `AudioListener` 挂在相机上，而相机离角色 **13 米**。
如果按第三人称游戏的常规取 `minDistance = 3`，角色身边发生的一切都会被衰减到约四分之一音量——
敌人站在面前开枪，听起来像在隔壁街区。

两条路，选了代价小的那条：

| 做法 | 评价 |
| --- | --- |
| 把听者挪到角色身上（俯视游戏的常规做法） | 最彻底，但要改两个场景里相机上的监听器与既有装配 |
| **把 `minDistance` 提到贴近相机距离（13 米）** | ✅ 采用：13 米内满音量、更远才衰减，左右声像仍然保留 |

另外，**本地玩家自己的声音一律不参与空间化**（`PlayAt(..., flat: true)`）：
自己的枪声、脚步、换弹不需要方位感（方位就是"我这里"），但必须满音量——
玩家判断"我这一枪打出去没有""背后是不是有人"全靠它。敌人的枪声仍然走 3D，那里最需要的恰恰是方位与距离。

## 4. 脚步：按距离而不是按时间

`FootstepCadence` 累计**走过的距离**，每走满一个步幅触发一步：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 步行步幅 | 0.95 米 | 卡通角色腿短，用成年人的 0.75 米会显得碎步 |
| 奔跑步幅 | 1.55 米 | 跑起来一步迈得更远，因此高速时脚步不会失控 |
| 最小间隔 | 0.2 秒 | 被外力推飞时的兜底，避免"机关枪般的脚步声" |
| 站定阈值 | 0.05 米/秒 | 低于它就把累计距离清零，避免走一步停一下再走时"补"出一步 |

按时间触发的话，走路与奔跑的脚步间隔会一模一样，奔跑听起来像"原地快速踏步"。

**步幅由 `IsSprinting` 决定，而不是在这里再比一次速度**：冲刺门槛会随负重变化
（超载时逻辑层会下调门槛），表现层自己拿一个写死的速度去比，迟早会和逻辑层对不上。
这一条与动画控制器是同一个原则——**奔跑的判定权只在模拟层手里**（详见
`Docs/12_用户反馈问题记录.md` 的 A-04）。

**路面判定**：从角色向上 0.8 米处向下打 2.4 米射线，取第一个**不属于玩家自己**的碰撞体，
按它的渲染材质名区分草地 / 硬地。这是个文本匹配的权宜之计，已记入待办（正式做法是给地面挂"路面类型"组件）。

## 5. 视觉特效

### 5.1 四个预制体

工具：`M7VfxPrefabBuilder.cs`。参数写死在构建器里而不是让人手点 Inspector——
"重新生成"必须能回到同一种观感。

尺寸的量化依据：**13 米外、55 度视场在 720 行画面里约 53 像素/米**，因此 0.1 米的粒子只有 5 像素，
肉眼几乎看不见。所有尺寸都按"至少 15 像素"反推。

| 预制体 | 贴图 | 数量 | 寿命（秒） | 尺寸（米） | 混合 |
| --- | --- | --- | --- | --- | --- |
| `Vfx_MuzzleFlash` | muzzle_03 + smoke_01 | 2 + 3 | 0.055~0.095 | 0.55~0.80 | 加法 + Alpha |
| `Vfx_ImpactSpark` | spark_02 | 12 | 0.15~0.35 | 0.14~0.26 | 加法 |
| `Vfx_ImpactDust` | smoke_05 | 7 | 0.35~0.70 | 0.34~0.58 | Alpha |
| `Vfx_ImpactFlesh` | smoke_05（染深红） | 9 | 0.20~0.40 | 0.16~0.30 | Alpha |

### 5.2 播放与回收

`CombatVfxDirector` 订阅 `WeaponFiredEvent`：

- 枪口火焰放在 `Origin`，朝向取"枪口 → 终点"的**水平投影**（直接用三维差值会让火焰朝地面倾斜）；
- 命中时在 `EndPoint` 生成特效，按 `HitTargetId` 是否为 0 区分"打在单位身上"与"打在环境上"；
- 每类特效一个对象池（容量 24、预热 6），回收时机由**粒子总寿命**推算（发射时长 + 最大粒子寿命，含子粒子系统），
  而不是写死秒数——策划把烟雾寿命从 0.4 秒调到 1.2 秒之后，写死的秒数会让烟雾播到一半被掐断。

### 5.3 与弹道的关系

弹道（`TracerRenderer`）在这一批**没有改动**：它在 M3 就已经验证过观感，
而且"贴地画线 + 保留真实高度"这条规则是踩过坑才定下来的（M7-P-06）。
这一批新增的枪口火焰与命中特效都是**在弹道之外叠加**的。

## 6. 玩家武器模型

### 6.1 为什么用 Quaternius 的 AK 与 Pistol

计划里原本推荐 Kenney Blaster Kit，实际选了 Quaternius Toon Shooter 的两把枪，理由是该包
**正是敌人角色手里那把枪**——同一个作者、同一套配色。玩家与敌人站在一起时不会有"两种美术风格"的割裂，
而且它随角色素材已经导入，零额外成本。

### 6.2 加工四件事

工具：`M7WeaponPrefabBuilder.cs`。

1. **转向**：源模型朝向 +X，项目的"前"是 +Z，预制体里直接绕 Y 轴 -90 度转正；
2. **缩放到设计长度**：步枪 1.25 米、手枪 0.46 米。**刻意比真实比例大约 40%**——
   13 米外每米只有约 53 像素，按真实比例做的枪在 62 度俯角下会被身体与手臂挡住大半；
3. **替换材质**：按源材质名映射到项目共用的 4 个 URP 材质（金属 / 深金属 / 灰 / 木），
   两把枪共用一套材质，材质数量不随武器数量增长；
4. **补枪口标记**：在枪管末端放一个名为 `Muzzle` 的空节点。运行时弹道起点、枪口火焰位置都取它。

### 6.3 灰盒兜底

`PlayerWeaponView` 优先用真实模型，两个预制体都拿不到时退回一个细长方块，
并按"武器占几格"决定长短。**缺素材不应该表现为"手里什么都没有"**——这条规则贯穿整个 M7。

枪口位置也由本组件提供：模型缺失时按"挂点沿朝向前推一个枪长"推算，
因此无论走哪条路径，弹道起点与枪口火焰都落在合理位置。

## 7. 接线与可维护性

### 7.1 表现层资产目录

`PresentationCatalog` 是一个 ScriptableObject，持有音效目录、两个武器预制体与四个特效预制体。
启动组件只引用它一个字段，而不是各挂七个引用——**每加一类美术资产就要在战局与安全屋两处各接一次线**
是漏接的主要来源（漏一个的症状是"安全屋有枪声、进图没有"这类只在一边出现的问题）。

### 7.2 一键加工

菜单 `RaidDemo/M7/重建表现层资产（音效/武器/特效）` 按依赖顺序执行：
音效 → 武器 → 特效 → 目录。顺序错了（先建目录再生成预制体）会得到一个引用为空的资产，
而空引用在游戏里的表现是"没有枪声、没有枪口火焰"，很容易被怀疑到代码。

### 7.3 场景接线工具

`M7PresentationWiringTool` 以**附加方式**打开两个场景、写入引用、保存并关闭，
不打扰编辑器当前打开的场景，也不重新生成场景（那会丢掉所有手工调过的内容）。
工具可反复执行——第二次跑不会产生任何差异。

两个场景生成器（`GreyboxSceneBuilder` / `SafeHouseSceneBuilder`）也同步写入了这条引用，
因此"重新生成场景"之后接线不会丢。
