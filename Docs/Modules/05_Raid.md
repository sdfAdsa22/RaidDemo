## 2. 设计前提

> 本项目的紧张感来自**玩家自己的贪心决策**，而不是来自"找不到撤离点"或"没带对钥匙"这类外部障碍。

由此推出三条贯穿 M5 的取舍：

1. **撤离点必须友好且明确。** 让玩家能放心地多搜一会儿，然后再为这个决定承担后果。
2. **搜刮必须有成本。** 开箱要花时间，而时间就是暴露自己的时间——这是贪婪循环的核心机制，
   没有它，"要不要再搜一个"这个问题就消失了。
3. **结算要回答一个问题："这一局我贪对了还是贪错了。"**
   因此结算界面必须有"带入价值 vs 带出价值"的对比，而不只是物品清单。

## 3. 一局的完整流程（玩家视角）

```text
主菜单：按「出击」
      ▼
进入战局：倒计时开始，玩家带默认装备出生
      ▼
搜刮与交火：在集装箱堆场、主厂房、装卸平台之间移动
           开箱需要读条；跑动与开枪会引来敌人
      ▼
做出决定：背包快满了 / 时间快到了 / 敌人太多了
      ▼
进入撤离区：站定读秒 10 秒（离开即中断并重置）
      ▼
结算：击杀数、带出的物品清单与总价值、存活时长、带入 vs 带出
      ▼
回到主菜单：可以立刻再来一局
```

**失败的两条路径**：阵亡；或时间耗尽。

## 4. 已确认的决策（2026-09-11）

| # | 决策点 | 结论 | 理由 |
| --- | --- | --- | --- |
| 1 | 地图尺寸 | **继续 60×60，重排布局** | 当前 AI 视距只有 9 米，地图放大会显得更空；先把闭环跑通，尺寸属于打磨 |
| 2 | 搜刮读条 | **要，约 2 秒；被打断即取消** | 没有读条，搜刮就没有风险成本，贪婪循环会塌掉一半 |
| 3 | 撤离点 | **固定全开（2~3 个）**，不做随机 | 保证"撤退总有一条路"；随机化留到以后 |
| 4 | 阵亡惩罚 | **结算如实显示损失，装备暂不真正持久化** | 真正的"丢失装备"需要仓库做载体，而仓库是 M6 的内容 |
| 5 | 一局时长 | **8 分钟** | 足够搜两三个区域加一次交火；太长会让"再来一局"的节奏变差 |

### 4.1 第 4 条的取舍需要写清楚

主文档 7.5 节写的阵亡惩罚是"丢失随身物品（保险箱除外）"。
但 M5 阶段**还没有仓库**，因此这一局丢掉的东西没有地方"真的丢"——
如果要在 M5 就做出真实的得失感，就必须把最简仓库提前做出来，范围会显著膨胀。

**当前选择**：M5 先让结算界面如实显示"损失了哪些、值多少"，让玩家理解规则；
等 M6 的仓库落地后，再把这份损失接到真实的物品上。

## 5. 实施顺序

每一阶段都能单独验证，最后一步才做整体联调——这样出问题时能立刻定位到是哪一段。

| 顺序 | 内容 | 单独验证方式 |
| --- | --- | --- |
| 1 | **地图分区重做** | 进图走一圈：四个区域能一眼分清，掩体与通道合理 |
| 2 | **战利品容器与掉落表** | 开若干箱：容器种类不同、掉落符合权重、稀有物不是随手就有 |
| 3 | **搜刮读条** | 站定开箱、移动打断、被打断后需要重新开始 |
| 4 | **撤离点与战局计时** | 进撤离区读秒、离开重置、时间耗尽判负 |
| 5 | **结算界面 + 极简主菜单** | 一局打完能看到完整结算，主菜单能再开一局 |
| 6 | **整体联调 + 录制演示** | 从主菜单一路打到撤离，全程无卡顿、无异常 |

## 6. 撤离规则（继承已冻结的设计）

| 规则 | 内容 |
| --- | --- |
| 数量 | 2~3 个 |
| 门槛 | **主流撤离点无条件可用**，不要求钥匙或付费 |
| 读秒 | 进入撤离区后倒计时 **10 秒**；离开即中断并**重置** |
| 附加条件撤离点 | 最多 1 个作为可选要素——**本次不做**（降级为以后的加分项） |

> 与塔科夫路线的区别：塔科夫的紧张感很大一部分来自"撤离条件的博弈"；
> 本项目故意把这道关卡拿掉，把压力全部压回玩家自己的贪心决策上。

---

## 7. 结算界面要展示的内容

| 项目 | 说明 |
| --- | --- |
| **带入 vs 带出** | 本次出击的收支对比：带入装备价值 vs 带出物品总价值。**这一项是结算的重点** |
| 带出的物品清单 | 逐项列出名称、数量、单价与合计 |
| 击杀数 | 击杀的敌人数 |
| 存活时长 | 从进图到撤离（或阵亡、超时）的时间 |
| 失败原因 | 阵亡 / 时间耗尽，以及**损失了哪些物品、值多少** |

## 8. 地图分区规划

主题已确认：**工业区 + 集装箱仓库**（主文档 7.5 节已论证：空间可读性强、天然适配搜刮节奏、
素材来源充足、与卡通低多边形风格契合）。

| 区域 | 玩法定位 | 灰盒表达 |
| --- | --- | --- |
| 集装箱堆场 | 主要搜刮区，视野开阔但有大量掩体 | 不同尺寸的箱体阵列（沿用现有集装箱） |
| 主厂房 | 室内近战交火，通道狭窄 | 长条形建筑 + 内部隔断 |
| 装卸平台 | 连接区，适合伏击 | 高台 + 坡道 |
| 外围围栏与出口 | **撤离点所在**，撤离前的最后风险 | 围栏 + 开阔地带 |
| 地下管廊（可选） | 侧翼绕行路线 | 长通道 + 分支——**本次可不做** |

地图仍然由代码生成（沿用灰盒场景生成器），保证可重复、可版本控制。

## 13. 落地记录（2026-09-11）

本节记录**实际做出来的样子**，与前面的规划对照阅读。

### 13.1 最终参数

| 项目 | 实际值 |
| --- | --- |
| 战局时长 | 480 秒（8 分钟），可在场景的 `SceneBootstrap` 上直接改 |
| 搜刮读条 | 2 秒，移动 / 阵亡即打断且**进度清零**（不保留） |
| 搜刮交互距离 | 2.2 米 |
| 撤离点 | 3 个固定点：北门 (0, 25.5)、西南角 (-25, -25)、东南货场 (25, -25)，判定半径 3.5 米 |
| 撤离读秒 | 10 秒，离开即中断并重置 |
| 战利品容器 | 地图上共 15 个，5 种定义 |
| 玩家出生点 | (-4, 0)，地图中央偏西的空地，三个分区都能一眼看到 |

### 13.2 容器与掉落

| 容器 ID | 名称 | 尺寸 | 抽取次数 | 定位 |
| --- | --- | --- | --- | --- |
| `crate.common` | 补给箱 | 5x4 | 4 | 量足、价值低，提供「安全收益」 |
| `crate.ammo` | 弹药箱 | 4x3 | 3 | 弹药压力主要靠它缓解 |
| `crate.medical` | 医疗箱 | 4x3 | 3 | 绷带与野战医疗包 |
| `crate.weapon` | 武器架 | 6x3 | 3 | 战斗力升级的主要来源 |
| `safe.rare` | 保险柜 | 4x4 | 3 | 全图唯一，约 94% 概率开出稀有以上物品 |

掉落采用「抽固定次数 + 权重」：每个箱子的产出数量稳定，不会出现空箱子。
随机源是注入的 `IRandomProvider`，同一颗种子必然产出同一批物资（可在场景上填 `m_LootSeed` 复现）。

### 13.3 地图分区

| 区域 | 实际表达 |
| --- | --- |
| 主厂房 | 西侧 17x28 的长条建筑，无屋顶，四个出入口 + 三道内部隔断 + 五处设备掩体 |
| 集装箱堆场 | 东侧 11 个箱体（含一处双层堆叠作地标），横竖交替摆放形成通道 |
| 装卸平台 | 南侧 22x9 的 1.2 米高台 + 两条坡道，台上有货箱与挡墙 |
| 外围环道 | 四段围栏 + 四处混凝土掩体，三个撤离点分布在地图三个方向 |

### 13.4 计划外的必要补充

| 补充项 | 为什么必须做 |
| --- | --- |
| **玩家移动碰撞** | 原本玩家可以穿过箱子与墙体（见排障 M5-P-03）。掩体若挡不住玩家，地图分区就没有意义 |
| **导航网格高度采样** | 装卸平台让地图第一次出现高低差，平面点 y 写死 0 会让台上的巡逻点直接寻路失败（M5-P-04） |
| **玩家地面吸附** | 角色原本固定在 y 等于 0，站上坡道与高台会陷进台体 |
| **移除阵亡后 4 秒复活** | 按第 4 节决策 4 执行：阵亡即本局结束 |

### 13.5 明确没做（与第 9 节一致）

仓库、商人、任务、经济循环、存档、保险箱、地图随机化、附加条件撤离点、多人同步。
结算界面会如实显示损失价值，但 M5 阶段**不会真正扣除物品**——界面里已写明这一点。

### 13.6 验证方式

| 层次 | 内容 |

### 13.7 M5.5 增量（2026-09-12）

闭环跑通之后追加了两项，都属于「让已有系统真正可用」，不是新系统：

| 增量 | 内容 | 为什么算在这里 |
| --- | --- | --- |
| **医疗品可以使用** | `MedicalBehavior`（回血量 + 读条时长）、`H` 键读条使用、受伤打断且不消耗、优先用刚好补满缺口的最小那件 | 补上 M5 搜刮的缺：没有回血，血量只是单向消耗，「再多搜一处」缺少支撑 |
| **右键上下文菜单** | 右键弹出 使用 / 装备 / 卸下 / 拆分，`Shift+右键` 直接拆分，战利品箱里的「使用」灰显 | 「使用」需要一个入口，而旧的右键只会执行固定动作 |

详细规则见 [`02_Inventory.md`](02_Inventory.md) 第 12 节；测试数从 322 增至 326。
