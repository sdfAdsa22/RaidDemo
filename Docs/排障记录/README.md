# 排障记录

> 这个文件夹记录**我在执行项目时遇到的问题，以及最终采用的解决方法**。
>
> 目的只有一个：**同一个坑不踩第二次**。所以每条都按「症状 → 定位 → 根因 → 做法 → 教训」记录，
> 并且尽量保留当时的**诊断证据**（日志、数值、命令输出），因为下次再遇到时，
> 有价值的是"怎么确认它是这个原因"，而不是"结论是什么"。

## 按症状速查

遇到问题时先在这里对一下，命中率最高：

| 症状 | 先查什么 | 大概率原因 |
| --- | --- | --- |
| 编译请求发出去了但永远不完成 | 读两次 `Time.frameCount` 看帧有没有在走 | 编辑器主循环停摆（M0-P-01 / M2-A04） |
| 改了配置但运行时不生效 | 去场景 / prefab 里看字段实际存的值 | 序列化值覆盖了代码里的新默认值（M2-A06） |
| 改了代码但行为没变 | 确认是否**完全退出并重进**播放模式 | 播放模式跑的是旧组件（M2-A07） |
| 播放模式下某段每帧逻辑"没生效" | 先确认帧在推进，再怀疑实现 | 编辑器失焦导致主循环不推进（M2-A04） |
| 程序集报"找不到类型" | 看被引用程序集有没有产出 DLL | 空程序集不产出产物 / `noEngineReferences`（M0-P-02） |
| `PathRulesTests` 报超限 | 用 `partial` 按职责拆文件 | 单文件超过 400 行（M2-A08） |
| 拆分枚举后已存在的资产数值全乱 | 看枚举是否被序列化进资产 | 枚举以整数写盘，成员变动会让后续值整体位移（M2-A10） |
| GitHub 推送连不上 | 逐个 TCP 测可用节点 | DNS 解析到不可达节点（M0-P-04 / M2-A12） |
| 补丁工具报 `invalid hunk header` | 把被打断的那段注释改写 | 中文长文本补丁会丢行首标记（M2-A02） |
| 测试失败 | **先判断是实现的错还是期望的错** | 期望值算错比实现错更常见（M2-A11） |
| 功能写了但用起来完全没反应 | 去启动层看它有没有被**创建** | 实现完成但没有接线（M2-U09 / M3-B06） |
| 明明做了音效却没声音 | 检查场景里有没有 `AudioListener` | 没有监听器时音频静默失效（M3-B07） |

## 记录规范

每条问题都包含以下小节：

| 小节 | 要求 |
| --- | --- |
| 症状 | 可观察到的具体表现，附上当时的日志或数值 |
| 定位过程 | 排除了哪些可能，靠什么证据收敛到根因 |
| 根因 | 一句话说清 |
| 做法 | 采用的做法，以及为什么选它 |
| 教训 | 下次可以提前做什么，避免重复 |

**新增记录时，请同时在本文档的「按症状速查」表里加一行**——
这张表才是这份文件夹真正会被反复使用的地方。
