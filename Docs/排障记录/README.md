# 排障记录

> 这个文件夹记录**我在执行项目时遇到的问题，以及最终采用的解决方法**。
>
> 目的只有一个：**同一个坑不踩第二次**。所以每条都按「症状 → 定位 → 根因 → 做法 → 教训」记录，
> 并且尽量保留当时的**诊断证据**（日志、数值、命令输出），因为下次再遇到时，
> 有价值的是"怎么确认它是这个原因"，而不是"结论是什么"。

## 按症状速查

遇到问题时先在这里对一下，命中率最高：

| 症状 | 先查什么 | 大概率原因 |
| --- | --- | --- |
| 编译请求发出去了但永远不完成 | 读两次 `Time.frameCount` 看帧有没有在走 | 编辑器主循环停摆（M0-P-01 / M2-A04） |
| 改了配置但运行时不生效 | 去场景 / prefab 里看字段实际存的值 | 序列化值覆盖了代码里的新默认值（M2-A06） |
| 改了代码但行为没变 | 确认是否**完全退出并重进**播放模式 | 播放模式跑的是旧组件（M2-A07） |
| 播放模式下某段每帧逻辑"没生效" | 先确认帧在推进，再怀疑实现 | 编辑器失焦导致主循环不推进（M2-A04） |
| 程序集报"找不到类型" | 看被引用程序集有没有产出 DLL | 空程序集不产出产物 / `noEngineReferences`（M0-P-02） |
| `PathRulesTests` 报超限 | 用 `partial` 按职责拆文件 | 单文件超过 400 行（M2-A08） |
| 拆分枚举后已存在的资产数值全乱 | 看枚举是否被序列化进资产 | 枚举以整数写盘，成员变动会让后续值整体位移（M2-A10） |
| GitHub 推送连不上 | 逐个 TCP 测可用节点 | DNS 解析到不可达节点（M0-P-04 / M2-A12） |
| 补丁工具报 `invalid hunk header` | 把被打断的那段注释改写 | 中文长文本补丁会丢行首标记（M2-A02） |
| 测试失败 | **先判断是实现的错还是期望的错** | 期望值算错比实现错更常见（M2-A11） |
| 功能写了但用起来完全没反应 | 去启动层看它有没有被**创建** | 实现完成但没有接线（M2-U09 / M3-B06） |
| 明明做了音效却没声音 | 检查场景里有没有 `AudioListener` | 没有监听器时音频静默失效（M3-B07） |
| 界面元素看起来被切掉一角 | **先测几何**，再看文本溢出模式 | 文本被自己的矩形裁掉，而不是锚点错（M3-U17） |
| UI 贴边内容被裁、换边换角都没用 | **先查 Game 视图的 Scale 滑块是不是 1x** | Scale > 1x 时内容超出面板，两侧一起被裁（M3-U22） |
| 某个按键完全没反应 | 看它是不是被写在另一个输入的提前返回之后 | 独立输入共享了同一条件分支（M3-U18） |
| 运行时的数值一直是 0、位置不动 | **连读两次 `Time.frameCount`**；再不行就 `Application.runInBackground = true` + `EditorApplication.QueuePlayerLoopUpdate()` | 编辑器失焦导致主循环停摆（M2-A04 / M4-C09） |
| 打空弹匣之后再也不开枪 | 看"结算完成"与"开始新一轮"的调用顺序 | 完成判定被重新开始覆盖（M4-C05） |
| 移动起来的单位打不中 / 看不见 | 先查物理同步（`Physics.autoSyncTransforms`），再查有没有缓存移动物体的位置 | Transform 驱动的角色不会自动同步到物理场景 / 缓存了出生点（M4-C07、C08） |
| 改了场景或资产生成器，但运行时行为没变 | 确认仓库里的**产物**（场景 / 资产）是否也更新了 | 改生成器 ≠ 改产物（M4-C10） |
| 编译报"找不到类型"，文件在带 asmdef 的子目录里 | 检查**同目录树下的每一个** asmdef | 主程序集加了引用，Editor 程序集没加（M4-C02） |
| 第三方包的类型报"不存在" | 去 `Library/PackageCache/` 里读源码确认命名空间 | 组件类与配套枚举可能来自不同命名空间（M4-C03） |
| 调试图形"画了但看不见" | 先看截图像素里到底有没有它 | 不透明度按装饰思路取值（M4-C13） |
| 验证结论与预期相反 | **先确认读到的是不是同一个世界**（对象是否已被杀死 / 复位） | 构造与读取之间隔了若干秒，战场已经变了（M4-C15） |
| 进游戏几秒就阵亡，操作输入没反应 | 看面板的状态迁移日志 | 出生点在敌人视野内，阵亡期间输入被刻意屏蔽（M4-C12） |
| 改了一处代码，行为没变（或别处悄悄变了） | 看是不是有两处**逐字相同**的代码 | 补丁按上下文匹配，只给一行时命中第一处（M4-C16） |
| 断言失败但看不出为什么 | **先把中间数据打进断言消息**再重跑 | 结果类失败信息不足以定位（M4-C16） |
| 做 A/B 对比时结论反复不成立 | 先问"除了要改的变量，还有谁会自己动" | AI 在巡逻、玩家在脚本化输入下前进，变量一直在漂移（M4-C17） |
| eval 里传送/装备了，读取却还是老样子 | 检查上一条 eval 是否返回 `Compilation Failed` | 一次性代码无类型检查，失败也不阻止下一条执行（M4-C18） |
| 读条走满了却什么也没发生，日志没有任何报错 | 读**中间状态**（进度、是否完成），再看事件有没有被订阅 | 事件发了但没接线（M5-P-05） |
| 玩家能穿过箱子与墙（AI 却会被挡住） | 看移动模拟里有没有碰撞查询 | 移动只有数学累加，没有世界碰撞契约（M5-P-03） |
| AI 站在高台上不动 / 半个身子埋进台面 | 看寻路与表现层有没有采样导航网格高度 | 平面点 y 写死 0，平台上的点不在网格上（M5-P-04） |
| 界面被一层颜色盖住、怎么等都散不掉 | 看反馈用的是不是 `Time.deltaTime` | `timeScale = 0` 后非缩放时间才有意义（M5-P-06） |
| 两个界面元素互相遮挡、时好时坏 | 对比两者的 `sortingOrder` | 层级取值撞车，渲染顺序取决于创建顺序（M5-P-10） |
| 生成器里同类对象全叠在一起 | 看工厂方法期望世界坐标还是相对坐标 | 坐标参照系不一致（M5-P-09） |
| 接口上「没有这个成员」，但实现类里有 | 先分清是漏了还是**刻意不给** | 接口为了不反向依赖而刻意裁掉的成员（M5-P-11） |
| 同一个文件又一次超出行数上限 | 别再想「写完再拆」 | 每加完一组方法就看一眼行数（M5-P-07 / M5-P-12） |
| 箱子里少了一件本该有的东西 | 按占地算一遍装箱，看是不是小件把空间切碎了 | 放置顺序未按大件优先（M5-P-13） |
| 面板消失，重开同一个也不回来 | 查持有视图的字段是否还指着被销毁的对象 | 视图销毁而状态未清（M5-P-14） |
| 装备穿上「感觉没用」 | 问两个问题：它改哪个数值？谁读它？ | 生效点缺失，没有报错（M5-P-15） |
| **新建一个场景后「看起来坏了」** | 对照战局逐项检查：组件创建了吗？序列化引用写了吗？每帧推送调了吗？ | **装配漏层**——逻辑复用，但装配每个场景要重写一遍（M5-P-16 ~ P-18） |
| 存档里出现「钱扣了但物品没到」 | 找到广播 / 写盘发生的位置 | 存档写进了复合操作的中间状态（M6-P-01） |
| 新开局某个功能失效，读档却正常 | 穷举所有启动路径的依赖注入 | 延迟注入只覆盖了其中一条路径（M6-P-02） |
| 面板文字与子视图标题叠在一起 | 把子视图标题高度算进布局 | 布局只按文字行高预留（M6-P-03） |
| 不可用的操作仍显示成可点按钮 | 按状态隐藏或置灰控件 | 视觉与可操作性不一致（M6-P-04） |
| 新接入一个系统就撞行数上限 | 先按新系统拆 partial | 功能边界变了、文件边界没变（M6-P-05） |
| 商人里买的东西在常规背包里看不到 | 看交易链路有没有发出背包事件；界面打开时是否重画 | 事件缺口 + 打开时不刷新（M6-P-06） |
| 实机测试后发现玩家存档被改 | 检查主档与 `.bak` 的差额反推操作 | 测试写进了真实存档（M6-P-07） |
| 玩家在坡道中段被无形墙卡住 | 打印胶囊扫掠命中面的法线 | 可行走斜面被当成障碍（M6-P-08） |
| 玩家走到栅栏/横梁下自动升到上方 | 检查向下射线是否取最高命中 | 横向物体顶面被当成地面（M6-P-09） |
| 主菜单点击一次后鼠标消失、按钮点不中 | 看每帧的光标锁定条件有没有读取流程状态 | 流程状态与输入策略不一致（M6-P-10） |
| 从 GreyboxRaid 启动，继续后画面静止 | 同时打印流程状态与活动场景名 | 流程状态与活动场景不一致（M6-P-11） |
| 相机停在原地、对着一个奇怪的东西 | 看启动对象的序列化引用是不是空的 | 生成器只挂了组件、没写引用（M5-P-16） |
| 交互提示有、模型却不见 | 查生成器里父物体的位置是在建子物体之前还是之后设的 | 父物体二次位移把子物体推出房间（M5-P-17） |

## 记录规范

每条问题都包含以下小节：

| 小节 | 要求 |
| --- | --- |
| 症状 | 可观察到的具体表现，附上当时的日志或数值 |
| 定位过程 | 排除了哪些可能，靠什么证据收敛到根因 |
| 根因 | 一句话说清 |
| 做法 | 采用的做法，以及为什么选它 |
| 教训 | 下次可以提前做什么，避免重复 |

**新增记录时，请同时在本文档的「按症状速查」表里加一行**——
这张表才是这份文件夹真正会被反复使用的地方。
