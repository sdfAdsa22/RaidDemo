# M11 · 问题记录与排障手册（工具链与环境）

> 用途：记录 M11 三版本全流程实机测试期间遇到的**工具链 / 环境**问题与规避办法，
> 防止后续会话重复踩坑。业务缺陷记在 `Docs/测试记录/M11_三版本全流程实机测试报告.md`。

## T-01 键盘注入不落地（鼠标有效、按键无效）

- 现象：`Click-RaidDemoAt` 有效，早期键盘注入（`keybd_event` / `SendKeys`）不生效，
  角色不移动、界面不响应。
- 原因：游戏走 Raw Input / 扫描码路径，虚拟键消息被忽略。
- 处理：`Library/TestRuns/tools/GameWindow.ps1` 改为**扫描码注入**
  （`Send-RaidDemoKey` / `Hold-RaidDemoKey`），注入后角色真实位移，验证通过。
- 避免：新写的自动化一律走扫描码；判定标准是"角色/界面真实变化"，不是命令返回成功。

## T-02 前台窗口被抢占（抖音等）

- 现象：游戏拿不住焦点，按键丢失；`GetForegroundWindow` 不是游戏窗口。
- 处理：注入前 `Set-RaidDemoTopMost` + `Focus-RaidDemoWindow`，
  截图改用 `Save-RaidDemoPrintWindow`（PrintWindow，不受遮挡影响）。
- 避免：每次注入前重新置顶、聚焦、复核焦点；截图一律用 PrintWindow。

## T-03 连续读取大截图导致 API 413（本次会话中断的根因）

- 现象：读取数十张 0.5~1.2 MB PNG 后，所有请求返回
  `413 Payload Too Large: Failed to buffer the request body: length limit exceeded`，
  重试同样失败，会话被终止（143）。
- 原因：每次请求都会重发整段对话历史；截图以 base64 进入请求（体积约 ×1.33），
  累计超过 API 网关的请求体缓冲上限。
- 处理：后续改为——截图先压缩成 ≤800px 宽、JPEG 约 70 质量的缩略图再查看；
  每个检查点把结论写进报告/台账落盘；批量看图交给子代理，原图不进主上下文。
- 避免：不读原始大图、不重复读同一张图、日志只读 tail、命令输出限行数。

## T-04 chroot 模式下 `-config` 传宿主路径

- 现象：云主机 chroot 启动时读不到配置，服务器启动失败并退化成单机客户端。
- 原因：`-config` 传入宿主路径，chroot 内不可见。
- 处理：改用环境变量传配置路径绕过，服务器恢复（当前云服以此方式运行）。
- 去向：属真实缺陷，已记入报告 **AR-01**（本轮只记录不修复）。

## T-05 客户端关闭期 Native Crash 记录

- 现象：`Player.log` 尾部在窗口关闭的同一时刻出现
  `Native Crash Reporting / UNKNOWN`（19:19）。
- 判断：疑似被外部终止导致，暂不认定为运行期崩溃。
- 处理：20:45 用主菜单 Esc 做了一次**正常退出**对照：
  进程干净退出，`Player.log` 尾部只有正常的 Input System 关闭序列，无 Native Crash。
- 结论：**结案**——19:19 的崩溃来自外部终止（会话中断杀掉进程），不属于游戏缺陷。

## T-06 背包 UI 拖拽 / 双击无法用注入验证

- 现象：`Drag-RaidDemoMouse` 与双击点击在背包界面上不生效（物品无位移、未装备）。
- 判断：注入事件与 UI 事件系统的兼容问题，非游戏功能结论。
- 处理：改用右键菜单 + 单击路径验证；仍无法验证的检查点标 BLOCKED，待人工复验。

## T-07 出口地图面板是键盘驱动，误用鼠标 / 回车会"看着像卡死"

- 现象：安全屋出口面板打开后，点地图行、按 Enter、按方向键都没有反应，
  看起来像界面卡住（上一轮会话在同一个地方耗到中断）。
- 原因：面板代码只看 `digit1Key` / `escapeKey` / `digit2Key` / `digit3Key`
  （`SafeHouseUI.MapPanel.cs` 的 `HandleMapPanelKeys`），**出击键是 `1`**，
  鼠标点击与回车本来就不在交互设计里。
- 处理：按 `1` 正常出击进图。
- 避免：UI 行为与预期不符时先读对应源码（`rg "关键文案" Assets -g '*.cs'`），
  再决定注入什么输入；不要靠猜。

## T-08 方向键注入必须带扩展键标志（否则被当成小键盘）

- 现象：`Send-RaidDemoKey -Key Down` 无任何反应。
- 原因：方向键扫描码带 E0 前缀；`MapVirtualKey` 返回的 Down 扫描码 0x50
  与小键盘 2 相同，不带 `KEYEVENTF_EXTENDEDKEY` 时事件被识别成小键盘。
- 处理：`GameWindow.ps1` 的 `Key()` 增加 extended 参数，
  方向键（Up/Down/Left/Right）注入时带 `KEYEVENTF_EXTENDEDKEY`。

## T-09 多客户端同机切换后，只 SetForegroundWindow 不吃键盘

- 现象：两个客户端同时运行，用进程号切换目标窗口（Focus 返回 `True`）后注入按键，
  目标客户端毫无反应（角色不走、F1 不开）；同一次在窗口里注入一次鼠标点击后，
  键盘立刻恢复正常。
- 原因：Unity 输入系统在窗口重新激活时以鼠标事件作为"真正前台"的信号；
  `SetForegroundWindow` 只改窗口 Z 序，目标进程不一定重新拿到键盘捕获。
- 处理：`GameWindow.ps1` 增加按进程号取窗口（`Get-RaidDemoWindow -ProcessId`），
  切换客户端后**先注入一次鼠标点击**（或右键，避免误开枪）再发按键。
- 避免：多客户端脚本里任何"换窗口"之后都补一次点击；判据以"角色真实位移"为准。

## T-10 整目录 scp 会覆盖云上配置；构建产物里的 server.sh 可能不是最新

- 现象：把 `Builds/ServerLinux/*` 整目录 scp 到云主机后，云上的
  `server.config.json` 被包内默认配置覆盖（saveDir 从 `server_saves_e2e`
  变回 `server_saves`）；同时包里的 `server.sh` 仍是旧版，不含 AR-01 的
  chroot 配置路径修复——服务器因此读不到配置，退化成客户端并开始热更资源。
- 原因：构建产物中的配置与脚本是"包内默认版"，与线上运行配置、仓库最新脚本不是同一份。
- 处理：整目录拷贝之后，单独再覆盖 `server.config.json` 与 `deploy/server.sh`，
  并在 `RAIDDEMO_CHROOT=/root/ubuntu-2204` 下 `./server.sh restart`。
- 避免：部署清单把"配置文件 + 脚本"列为**单独步骤**；出包脚本应带上最新的
  `deploy/server.sh`（本次已记入报告 6.3，待后续并入自动化）。
