## T-01 构建期间 Unity 卡在 "Compiling Scripts"（编译进程僵死）

**现象**：出完客户端（`Builds/Update/1.0.2` 已落盘）后立刻发起"构建专用服务器（Windows）"，
Unity 弹出 `Compiling Scripts (busy for 10:37)...`，进度条走满停在
`Compiling C# (RaidDemo.Data)`；点 `Cancel` 后变成 `Cancelling` 也一直不结束。

**判据（怎么确认不是"正常慢"）**：

- Unity 主进程 20 秒只涨 ~1 秒 CPU；`Unity.ILPP.Runner` 的 CPU **完全不涨**；
- `Builds/ServerWindows` 的时间戳停在上一轮构建时间；
- 枚举 Unity 的可见窗口能看到 `Compiling Scripts (busy for …)` 这个模态窗口。

**根因（结论）**：Unity 6.6 的脚本编译阶段偶发僵死，与本次改动的代码无关
（同一份代码在此之前刚编译通过、测试全绿）。

**处置**：结束 Unity 进程（含 `Unity.ILPP.Runner`）后重开工程，重新发起同一个构建即可，
第二次 50 秒就完成。

**下次的省时做法**：构建期间**不要再对同一个编辑器发任何 CLI 命令**
（`eval` / `editor_status` 等）——本次僵死前正好并发发过多条命令。
判断"在忙"用窗口标题 + CPU 采样，而不是继续往编辑器里塞命令。

## T-02 给客户端/服务端传带空格的 `-logFile` 会拆参导致进程秒退

**现象**：用 `Start-Process -ArgumentList '-logFile','D:\unity game\demo\Library\...\a.log'`
起的客户端进程立刻消失，既不联网也不生成日志。

**原因**：`Start-Process -ArgumentList` 是**拼接**成命令行字符串，不做逐参数转义；
路径里的空格把它拆成了两个参数，Unity 的启动参数解析拿到残缺值。

**处置**：两条路任选

1. 参数里自带引号：`-ArgumentList '-logFile','"D:\path with space\a.log"'`；
2. 传**不含空格**的相对路径（服务端/客户端以各自工作目录为基准），
   跑完再把日志复制进证据目录。

**备注**：服务端与客户端的 `-logFile` 都受这条影响；M11 期间用的是相对路径，所以没踩到。

## T-03 含 `Start-Process` 的复合命令会被安全策略拦下

**现象**：把"起进程 + 等待 + 请求状态页"写在一条命令里时，整条命令被拒绝执行
（提示 blocked by policy）；把同样内容拆成"起进程"与"检查"两条命令则正常。

**处置**：起后台进程用**单条最小命令**，后续检查另起一条命令。
这条是执行环境的限制，不影响产品行为，但会浪费排查时间——先记在这里。
