# RaidDemo — 3D 斜俯视搜打撤射击游戏

> 一款卡通风格的 3D 斜俯视（45°）搜打撤（Extraction Shooter）游戏：携带装备进入地图，搜刮物资、与 AI 交火，在限时内抵达撤离点，将战利品带回仓库用于变卖、升级装备与接取任务。
>
> 联机支持 2~4 人 PVE 合作（专用服务器）。

**对标游戏**：[《逃离鸭科夫》](https://store.steampowered.com/app/3105440/)（Escape from Duckov）。
本项目不是塔科夫的仿制——两者的紧张感来源完全不同：塔科夫来自对枪与穿甲博弈，
本项目来自**贪心与撤离时机的抉择**。

## 项目简介

**核心循环**：进入地图 → 搜刮物资 → 与 AI 交火 → 抵达撤离点 → 回收战利品 → 变卖/升级装备/接任务 → 再次出击。

### 核心玩法支柱：贪婪循环

本项目的全部系统都服务于一个循环：

```text
搜刮  →  贪婪（背包快满了，但那个箱子还没开）
      →  负重（越拿越重，跑得越慢、体力掉得越快、噪音越大）
      →  撤离（赌一把再搜一个，还是现在就撤）
      →  带出的物资成为下次出击的资本  →  回到搜刮
```

判断一个功能该不该做的标准是：**它是否让"要不要多拿一件"这个问题变得更难回答。**
完整说明见技术基准文档 7.12 节。

**玩法特征**

- **网格背包**：物品按格子占用空间，支持旋转、堆叠、拆分与嵌套容器
- **负重压力**：携带重量影响移动速度、体力消耗与噪音半径——这是贪心的物理代价
- **奔跑与体力**：两档移动速度（步行/奔跑）；体力归零后进入力竭状态，无法奔跑
- **搜刮风险**：容器需要搜索时间，战斗收益与撤离时限形成风险决策
- **会听也会看的 AI**：近身（6 米内）必定发现，中距离（6~9 米）只会让它**警惕**——停下、转向、盯着你看 3 秒才动手；噪音按移动档位分档（步行 4 / 奔跑 8 / 超载 12 米），**跑动与超重会把敌人引过来**；AI 会巡逻、调查动静、保持距离交火，并在重伤时撤退
- **开枪是有代价的**：射程即枪声半径（手枪 8 米 / 步枪 12 米），**打不中的枪声一样会把敌人引过来**——武器射程压到近战范围，正面交火很难不被其他人听见
- **等级化护甲**：护甲按 1~4 级提供 20%~65% 减伤，可读性优先（不做塔科夫式的穿透概率）
- **友好撤离**：多个撤离点，主流撤离点无条件可用，让玩家能放心多搜一会儿
- **局外成长**：仓库、固定价格商人（买价 / 75% 收购价）、五个固定任务与本地存档构成循环；
  护甲已有 2 级钢盔 / 3 级背心，更多装备等级与收集图鉴推迟到 M8 开篇

**目标定位**：本项目是面向 **Unity 客户端开发岗位**的作品集项目，评价重心为**系统完整性与代码质量**，而非美术表现。

## 运行方式

### 环境要求

| 项目 | 要求 |
| --- | --- |
| Unity 版本 | **6000.6.0f1**（Unity 6） |
| 平台 | Windows 10 / 11（本项目仅面向 Windows） |
| 图形 API | DirectX 11 / 12 |

### 启动步骤

1. 克隆仓库（仓库根目录即 Unity 工程根目录）
2. 用 **Unity Hub** 添加该目录，使用 Unity `6000.6.0f1` 打开
3. 首次打开时 Unity 会自动还原 `Packages/manifest.json` 中声明的依赖包
4. 打开启动场景 `Assets/Game/Content/Scenes/SafeHouse.unity`，点运行

> **进游戏后**：先看到主菜单，点「开始 / 继续」或按 `Enter` 进入安全屋；
> 在安全屋里走到北墙中间的商人处按 `E` 买装备、接任务，走到仓库前按 `E` 整理装备，
> 走到东侧出口按 `E`、再按 `1` 进入工业区。撤离或阵亡后回到安全屋。
> 存档写入 `Application.persistentDataPath` 下的 `raid_demo_save.json`，主菜单的「新游戏」
> 会清空仓库、金币与任务进度并重置为 5,000 金币。整条流程不需要重启编辑器。
>
> **推荐从 `SafeHouse.unity` 启动。** 如果编辑器当前打开的是 `GreyboxRaid.unity` 并直接按 Play，
> 主菜单仍会出现；点「继续游戏」会自动加载 `SafeHouse`，不会停留在未激活的战局场景。

> 灰盒场景由菜单 **`RaidDemo → 生成灰盒测试场景`** 生成；物品资产由菜单
> **`RaidDemo → 生成初始物品资产`** 生成。两者都是可重复执行的，场景与资产均已提交，
> 正常克隆后直接运行即可，不需要先执行菜单命令。

> 工程使用 Unity 的 **Force Text** 序列化与 **Visible Meta Files**，`.meta` 文件已一并提交，无需任何手动配置。

### 联机模式（专用服务器）

**一键开服（推荐）**：双击服务器包里的 `RaidDemo.ServerHost.exe`（Windows）或
`./server.sh start`（Linux）——端口、房间名、存档目录等在 `server.config.json` 里改，
面板上能看到在线人数、当前世界与实时日志，并可一键复制连接信息给队友。
服务器包用 `pwsh -File Tools/ServerHost/pack_server_package.ps1 -Zip` 生成
（详见 [`Docs/03_模块设计/10_联机.md`](Docs/03_模块设计/10_联机.md) 第 34 节）。

**手工联调（1 服务器 + 2 客户端）**：

```powershell
# 服务器（普通构建 + -server；也可用菜单 RaidDemo/M9/构建专用服务器（Windows）出独立服务器包）
RaidDemo.exe -server -port 7777 -room 测试房间 -batchmode -nographics -logFile server.log

# 客户端（同一台机器跑多个时要改 -nickname；不同机器各跑一条）
RaidDemo.exe -connect 127.0.0.1:7777 -nickname 甲 -passphrase 246810 -autoroom
RaidDemo.exe -connect 127.0.0.1:7777 -nickname 乙 -passphrase 246810 -autoroom
```

常用服务器参数（完整说明见 `Assets/Game/Bootstrap/Session/LaunchOptions.cs` 的注释）：

| 参数 | 用途 |
| --- | --- |
| `-port` | 监听端口（默认 7777） |
| `-room` | 默认房间名 |
| `-autostart <秒>` | 房间成立后自动开局（验收 / 录制用，省掉手动点出口） |
| `-raidDuration <秒>` | **战局总时长上限**（默认 480，0 = 不判超时）——这是服务器真正用来结束一局的时钟 |
| `-dashboardPort` / `-discoveryPort` | 状态页（默认 8080）与局域网发现（默认 47777）；`0` 表示关闭 |
| `-saveDir` | 服务端存档目录（相对路径，默认 `server_saves`） |

**云主机 / 局域网 Linux 部署**：三步——构建（菜单 `RaidDemo/M9/构建专用服务器（Linux）`）、
上传构建产物与 `deploy/` 下的脚本、启动（`./server.sh start`）。
完整步骤（含端口放行与 glibc 兼容层）见 **[`deploy/README.md`](deploy/README.md)**。

**玩家连接**：客户端主菜单点「联机」→ 输入服务器地址与昵称 → 创建 / 加入房间；
服务器状态页（浏览器只读查看房间、玩家与日志）：`http://<服务器IP>:8080/`。

### 启动器与更新源（玩家侧的安装 / 更新方式）

正式的分发形态不是"直接发一个 exe"，而是**启动器 + 更新源**：

```powershell
# 构建工具（自包含单文件，目标机器无需 .NET 运行时）
dotnet publish Tools/Launcher/RaidDemo.Launcher.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o Builds/Tools/Launcher-win
dotnet publish Tools/UpdateSource/RaidDemo.UpdateSource.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o Builds/Tools/UpdateSource-win

# 起一个本机更新源（写操作需要口令）
RaidDemo.UpdateSource.exe --root <更新源目录> --port 8090 --token <口令>

# 启动器：检查 / 更新 / 更新并启动（图形界面直接双击 RaidDemo.Launcher.exe）
RaidDemo.Launcher.exe --check  --source http://127.0.0.1:8090 --root <安装根>
RaidDemo.Launcher.exe --update --source http://127.0.0.1:8090 --root <安装根> --launch
```

发布一个新版本的完整流程（Unity 菜单 → 上传 → 面板发布）见
[`Tools/UpdateSource/README.md`](Tools/UpdateSource/README.md) 与 [`Tools/Launcher/README.md`](Tools/Launcher/README.md)：
菜单 `RaidDemo/M10/① 构建客户端（Windows）并生成更新清单` → `④ 配置 Addressables 分组` →
`⑤ 构建资源` → `⑥ 生成更新清单（本体 + 资源）`，把 `Builds/Update/<版本>/` 上传到更新源的
`versions/<版本>/` 后点发布。启动器把更新源与默认服务器地址通过 `-updatesource` / `-connect` 传给游戏，
资源层由游戏内的热更流程下载（先比内容版本，只下变化的文件，逐文件校验 SHA-256）。

## 操作说明

> 输入系统基于 Unity **Input System** 实现。下表中标注了尚未接入的里程碑。
>
> **注意**：蹲下与爬下已按设计决策砍掉（见 [`ADR-005`](Docs/04_技术决策/ADR-005-对标基线修正为逃离鸭科夫.md)），不对应任何按键。

**战局内**

| 操作 | 按键 | 状态 |
| --- | --- | --- |
| 移动 | `W` `A` `S` `D`（或方向键） | 可用 |
| 瞄准 | 鼠标 | 可用 |
| 奔跑 | `左 Shift` | 可用（重装以上状态无法奔跑） |
| 切换武器 | `鼠标滚轮`（上滚 / 下滚）或 `1` / `2` | 可用（主武器与副武器互换） |
| 换弹 | `R` | 可用（**只从弹药挂取弹**） |
| 射击 | 鼠标左键 | 可用 |
| 搜刮容器 | `E` | 可用（站定读条 2 秒，移动即打断） |
| 打开 / 关闭背包 | `Tab` | 可用（双击快速搬运，右键菜单，`Shift+右键` 直接拆分，`F` 整理） |
| 使用医疗品 | `H` | 可用（读条 1.5~3 秒，受伤即打断且不消耗；再按一次取消） |
| 暂停 / 继续 | `Esc` | 打开暂停菜单；再按一次 `Esc` 继续游戏 |

> **右键菜单**：右键点击物品弹出菜单，可选 **使用 / 装备 / 卸下 / 拆分**。
> 战利品箱里的物品不能用「使用」（要拿进自己包里才行），不可用的选项会**灰显**而不是隐藏。

**主菜单（出击准备）**

| 操作 | 按键 | 说明 |
| --- | --- | --- |
| 继续 / 开始游戏 | `Enter` / 点击主按钮 | 有存档时继续上次进度；没有存档时以 5,000 金币开始（启动时主菜单只是盖在安全屋上的一层） |
| 新游戏 | 点击「新游戏」两次 | 清空仓库、金币与任务进度；第一次点击只是二次确认 |
| 退出游戏 | `Esc` | 编辑器里退出播放模式，构建里真正退出 |

**安全屋（局外空间）**

| 操作 | 按键 | 说明 |
| --- | --- | --- |
| 移动 / 瞄准 | `WASD` / 鼠标 | 与战局完全一致 |
| 与设施交互 | `E` | 走到**仓库 / 商人 / 出口 / 衣柜 / 图鉴展示板**前按 `E`；商人打开交易与任务界面，衣柜换角色，图鉴展示板打开收集图鉴 |
| 试枪 | 鼠标左键 | 对着东侧靶子开枪：有弹道、枪声与**伤害数字**（打中靶心是金色） |
| 打开背包 | `Tab` | 右侧面板显示仓库；把装备拖到身上 |
| 选择地图出击 | `1` | 在出口打开地图选择后按 `1` 去工业区（另两张上锁） |
| 暂停 / 继续 | `Esc` | 打开暂停菜单；再按一次 `Esc` 继续游戏 |

> **商人界面**：顶部两个页签 `购买 / 任务`，右侧始终显示仓库。
> 购买直接把物品放进仓库，仓库满时不扣钱；出售入口常驻在仓库下方——
> 右键仓库物品弹出菜单点「出售」可卖单件，点「出售」按钮进入批量模式后
> 左键点选多件（未选中压暗，选中保留品质色并显示白描边与 ✓，实时显示预计收入），点「确认出售」一次结算并自动退出模式；
> 单件或批量总价 ≥ 10,000 时弹二次确认；金币与仓库总价值常驻显示。
> 任务页可以接取任务、追踪进度、上交指定物品与领取奖励。

> **这一局输得起多少，由你自己决定**：带得越多，撤离后赚得越多，阵亡时亏得也越多。
> 阵亡与超时会丢掉**背包里的 + 身上穿的**，而**仓库里的东西绝对安全**。
>
> **暂停菜单**提供「返回主界面」与「返回桌面」两个选项。
> 战局中返回主界面会**放弃本局**，随身携带物全部丢失（仓库不受影响）；
> 返回桌面后未撤离的随身物品会在下次启动时按阵亡处理。

**战局规则**

| 规则 | 内容 |
| --- | --- |
| 一局时长 | 8 分钟，时间耗尽判负 |
| 阵亡 | 本局结束（**没有复活**），结算如实显示损失价值 |
| 撤离 | 站进绿色撤离点读秒 10 秒，离开即重置 |
| 背包里的物品 | 撤离成功才真正入库；阵亡、超时或战局中途强退都会丢失随身携带物，仓库不受影响 |
| 结算去处 | 结算界面只保留一个「返回安全屋」按钮（`Esc`）；下一局由安全屋出口决定 |

> 敌人阵亡后会变成灰色并停止行动，状态颜色为：**绿=巡逻、橙=警惕、黄=调查、红=交战、蓝=撤退**。

## 技术栈

### 设计基线

| 项目 | 结论 |
| --- | --- |
| **对标游戏** | **《逃离鸭科夫》（Escape from Duckov）** |
| 明确不对标 | 《逃离塔科夫》——紧张感来源、战斗基调、美术风格均不同 |
| 核心支柱 | 贪婪循环（详见上文） |
| 移动姿态 | 仅步行 + 奔跑两档（无蹲下、无爬下） |
| 体力作用 | 只作用于移动，不影响射击精度 |
| 护甲模型 | 等级减伤，可读性优先 |

所有设计取舍均以"是否强化贪婪循环"为判断标准。若某功能无法回答这个问题，则不做。

| 类别 | 技术 | 版本 |
| --- | --- | --- |
| 引擎 | Unity | 6000.6.0f1 |
| 渲染 | Universal Render Pipeline (URP) | 17.6.0 |
| 输入 | Input System | 1.20.0 |
| 寻路 | AI Navigation（NavMesh） | 2.0.14 |
| 相机 | Cinemachine | 6.6.0（Unity 6 内置版） |
| 测试 | Unity Test Framework | 1.8.0 |
| 联机 | Netcode for GameObjects | 2.13.2 |
| 资源热更 | Addressables | 2.10.3 |
| 代码热更 | HybridCLR | — |

> Netcode for GameObjects 与 Addressables 都是**已安装并在用**的依赖（M9 / M10 的核心）。
> HybridCLR 一栏写"—"是有意的：ADR-008 决定代码更新走启动器的本体更新，
> 因此它**不作为包依赖引入**——加了它就得让 38 个带脚本的资产进 Addressables，
> 而在当前 Unity 版本下进程内热更本身又不可用（探针结论见 [`Docs/03_模块设计/11_热更新与分发.md`](Docs/03_模块设计/11_热更新与分发.md) 第 12 节）。

## 架构设计

采用**分层 + 程序集隔离**的架构，依赖方向单向，低层不反向引用高层。

```text
                      ┌──────────────┐
                      │  Tests.*     │
                      └──────┬───────┘
                             │
        ┌────────────────────┼────────────────────┐
        │                    │                    │
   ┌────▼────┐         ┌─────▼─────┐        ┌─────▼────┐
   │  UI     │         │   Raid    │        │   Meta   │
   └────┬────┘         └─────┬─────┘        └─────┬────┘
        │                    │                    │
        │        ┌───────────┴───────────┐        │
        │   ┌────▼─────┐            ┌────▼────┐   │
        │   │    AI    │            │ Combat  │   │
        │   └────┬─────┘            └────┬────┘   │
        │        │      ┌───────────────┘        │
        │   ┌────▼──────▼────┐                   │
        └───►   Inventory     ◄──────────────────┘
                 └─────┬─────┘
                  ┌────▼────┐
                  │  Data   │
                  └────┬────┘
                  ┌────▼────┐
                  │ Kernel  │
                  └─────────┘
```

**关键设计**：

- **逻辑与表现分离**：业务逻辑不依赖 `MonoBehaviour` 与场景，可在 EditMode 测试中直接验证
- **单一数据来源**：客户端与服务端共用同一套规则代码（`Shared` 层不引用 `UnityEngine` 运行时类型）
- **状态变更单一入口**：所有玩家意图经 `CommandRouter` 执行，使单机与联机共用同一套逻辑
- **数据驱动**：物品、掉落、数值均由 ScriptableObject / JSON 配置，扩充内容无需改动代码

完整说明见 [`Docs/02_架构与工程.md`](Docs/02_架构与工程.md)。

## 工程规范

本项目遵循一套明确的工程约束，核心几条：

| 约束 | 说明 |
| --- | --- |
| **禁止绝对路径** | 源码与配置中不允许出现任何本机路径，保证克隆即可运行；并有单元测试自动扫描拦截 |
| **程序集隔离** | 各模块独立 asmdef，依赖方向单向，防止架构腐化 |
| **注释解释为什么** | 公开 API 必须有 XML 文档注释；数值参数注明量纲与调参影响 |
| **测试锁定规则** | 背包占位、伤害公式、状态机迁移等易错逻辑均有 EditMode 单元测试 |
| **数据与代码分离** | 新增物品/武器只需新增数据资产，不需要改动逻辑代码 |

## 已知限制

本项目为个人作品集 Demo，存在以下明确的范围限定：

| 限制 | 说明 |
| --- | --- |
| **仅 Windows 平台** | 不做主机 / iOS / Android 适配 |
| **联机规模有限** | 支持 2~4 人 PVE 合作；不包含 PVP、匹配系统、账号体系与反作弊 |
| **地图数量** | 1 张地图（工业区 + 集装箱仓库），优先保证系统完整度 |
| **经济深度有限** | 商人只有一个、固定价格、无限库存；动态价格、库存刷新、声望、跳蚤市场与保险均推迟（P-02） |
| **任务与收集** | 固定 5 个任务，不做随机任务；收集图鉴已做（M8 批次 1），但没有跨局的长线成长与赛季内容 |
| **装备阶梯有限** | 护甲 1~4 级、手枪 / 步枪 / 冲锋枪 / 霰弹枪各一支，没有配件系统与改装 |
| **存档只在本机** | 只保存局外进度，不做云存档、不做战局中途存档；V1 存档结构带版本号，后续字段改动需要补迁移 |
| **AI 的灰盒边界** | AI 之间不做避让、不做掩体寻优，交战时会走到期望距离但不主动找掩体；撤退仍用匀速恢复代替医疗物品 |
| **进程内代码热更不可用** | HybridCLR 社区版在当前 Unity 版本（6000.6）下无法与 il2cpp 配合，探针 27 处编译错误；代码更新改由启动器替换本体承担（ADR-008），代价是必须重启进程 |
| **联机没有反作弊** | 服务器会校验上行输入（非法槽位、NaN、超范围一律丢弃），但不做反外挂：这是合作 PVE，不是竞技 |
| **性能未做量测** | 没有 Profiler / 内存快照 / GC 统计的量化数据；已知的优化项（伤害数字与弧形体力条未走对象池等）记在审查复核文档里 |
| **美术为卡通风低多边形** | 美术表现非本项目重点，资源在 M7 阶段统一替换；素材授权见下方「素材来源与授权」 |
| **仍有排期中的技术债** | 经一轮代码自查后，第三档（确定性 / 表现层存量）与第四档（架构与规范门禁，如 50 行方法、裸日志、公开字段的自动门禁）**按计划推迟** |
| **换包时不会丢东西，但可能暂时不缩容** | 背包塞满时卸下它，容量会保持到腾出空间为止（自愈）。正式版应改为「拒绝卸下并提示」 |

主动推迟的功能清单见 [`Docs/02_架构与工程.md`](Docs/02_架构与工程.md) 的「范围边界」。

## 开发方式说明

本项目采用 **AI 辅助开发**：选题、范围界定、系统与架构取舍、玩法数值与手感调校、美术方向、验收测试与最终决策均由作者负责；AI 编码助手（Codex）承担实现与测试代码的编写、文档草稿与素材调研。

为保证质量，工程建立了 700+ 项自动化测试与规范门禁（例如"单文件不超过 400 行"由测试用例强制），AI 的产出必须通过测试与实机验收才能进入版本。全部提交记录与最终验收由作者完成。

协作模式与工程护栏的详细说明见 [`Docs/01_项目概述.md`](Docs/01_项目概述.md) 第 5 节。
